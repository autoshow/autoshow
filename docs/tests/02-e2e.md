# E2E Suites

The E2E layer is definition-driven. Static JSON definitions live under `tests/test-definitions/`, and the runtime helpers live under `scripts/test/harness/`.
Transcription verify definitions are grouped by `src/models/models-config/transcription-config.ts` category under `tests/test-definitions/verify/transcription/whisper`, `tests/test-definitions/verify/transcription/diarization`, and `tests/test-definitions/verify/transcription/streaming`.
The canonical E2E launcher is `scripts/test/e2e.ts`, which both `bun as runner e2e ...` and direct standalone E2E runs use.

## Running

```bash
# curated minimal suite
bun as runner e2e

# ultra-small curated suite
bun as runner e2e --e2e-mode minimalist

# cheapest-model service suites
bun as runner e2e --e2e-mode services
bun as runner e2e --e2e-mode services2x

# verify-tagged E2E definitions
bun as runner e2e --e2e-mode verify
bun as runner e2e --concurrency 5 --e2e-mode verify

# explicit minimal mode
bun as runner e2e --e2e-mode minimal

# one definition by path
bun as runner e2e tests/test-definitions/verify/transcription/whisper/verify-transcription-groq-whisperv3turbo.json

# directories or globs
bun as runner e2e tests/test-definitions/verify/transcription
bun as runner e2e tests/test-definitions/verify/transcription/whisper
bun as runner e2e tests/test-definitions/verify/transcription/diarization

bun as runner e2e --concurrency 5 tests/test-definitions/verify
bun as runner e2e --input 1m-streaming,2m-streaming tests/test-definitions/verify/transcription
bun as runner e2e --input 1m-local,10m-direct 'tests/test-definitions/prompts/**/*.json'
```

### Cost-Only Mode

```bash

bun as runner e2e --test-price tests/test-definitions/verify/transcription/streaming
```

For the standalone entrypoint, use `bun scripts/test/e2e.ts ...` with the same E2E-specific flags and path arguments.

## Runner Modes

- `minimal`: curated representative subset and the default when no path args are provided
- `minimalist`: ultra-small curated subset spanning the main verify categories without changing the default
- `services`: cheapest-model-per-service suite
- `services2x`: two-cheapest-models-per-service suite
- `verify`: all definitions tagged `verify`
- `all`: all discovered definitions
- `paths`: inferred when you pass JSON paths, directories, or globs

## Concurrency

The CLI runner supports bounded definition-level concurrency.

- `bun as runner e2e ...` defaults to concurrency `10`.
- Use `--concurrency <n>` to change the cap.
- Each definition gets an isolated artifact directory, so concurrent runs do not share output paths.
- Definitions tagged `serial` still run through `test.serial(...)` when suite concurrency is greater than `1`.

## Input Variants

The launcher can override a definition's source with named variants passed to `--input` as a comma-separated list.

Internally, the runner selects one of two hard-coded variant maps:

- `AUDIO_VARIANTS` for non-document definitions
- `DOCUMENT_VARIANTS` for definitions tagged `document` or `document-parsing`, or definitions with a `document` block

Available variant names:

| Category | Variants |
|----------|----------|
| Audio | `1m-local`, `1m-direct`, `1m-streaming`, `2m-streaming`, `5m-direct`, `10m-direct`, `20m-direct` |
| Document | `1p-local`, `1p-direct`, `3p-local`, `10p-direct` |

Audio variant map:

| Variant | Resolved input |
|---------|----------------|
| `1m-local` | `{ "type": "local", "path": "scripts/test/fixtures/input/1.mp3" }` |
| `1m-direct` | `{ "type": "url", "url": "https://ajc.pics/autoshow/1.mp3", "urlType": "direct-file" }` |
| `1m-streaming` | `{ "type": "url", "url": "https://www.youtube.com/watch?v=nXtaETBZ29g", "urlType": "streaming" }` |
| `2m-streaming` | `{ "type": "url", "url": "https://www.youtube.com/watch?v=MORMZXEaONk", "urlType": "streaming" }` |
| `5m-direct` | `{ "type": "url", "url": "https://ajc.pics/autoshow/5.mp3", "urlType": "direct-file" }` |
| `10m-direct` | `{ "type": "url", "url": "https://ajc.pics/autoshow/10.mp3", "urlType": "direct-file" }` |
| `20m-direct` | `{ "type": "url", "url": "https://ajc.pics/autoshow/20.mp3", "urlType": "direct-file" }` |

Document variant map:

| Variant | Resolved input |
|---------|----------------|
| `1p-local` | `{ "type": "local", "path": "scripts/test/fixtures/input/1.pdf" }` |
| `1p-direct` | `{ "type": "url", "url": "https://ajc.pics/autoshow/textract-1.pdf", "urlType": "document" }` |
| `3p-local` | `{ "type": "local", "path": "scripts/test/fixtures/input/3.pdf" }` |
| `10p-direct` | `{ "type": "url", "url": "https://ajc.pics/autoshow/textract-10.pdf", "urlType": "document" }` |

Example:

```bash
bun as runner e2e --input 1m-streaming,2m-streaming tests/test-definitions/verify/transcription
bun as runner e2e --input 1m-local,10m-direct 'tests/test-definitions/prompts/**/*.json'
```

Rules:

- Each definition resolves to exactly one input source.
- The runner does not duplicate one definition into multiple tests.
- When multiple variants are provided, the first compatible variant in request order is applied to each definition.
- Streaming definitions only take streaming variants; local/direct audio definitions only take local/direct variants; document definitions only take document variants.
- Unknown variant names fail early.
- Definitions with no compatible requested variant keep their original input.
- If none of the selected definitions are compatible with any requested variant, the run fails early.

## Definition Format

Definitions describe the input source plus step-specific model selections:

```json
{
  "id": "verify-llm-openai-gpt54",
  "name": "Verify: OpenAI GPT-5.4",
  "tags": ["verify", "llm", "openai"],
  "input": { "type": "local", "path": "scripts/test/fixtures/input/1.mp3" },
  "transcription": { "service": "groq", "model": "whisper-large-v3-turbo" },
  "llm": { "service": "openai", "model": "gpt-5.4", "prompts": ["shortSummary"] },
  "tts": { "enabled": false },
  "image": { "enabled": false },
  "music": { "enabled": false },
  "video": { "enabled": false }
}
```

## Execution Model

The CLI runner manages the server lifecycle:

1. Build the app with `bun run build`.
2. Start `bun run start` on an available port with `NODE_ENV=test`.
3. Upload inputs, submit jobs, poll for completion, and verify outputs.
4. Write JSON reports and logs under `artifacts/logs/` unless `TEST_RUN_OUTPUT_DIR` is set, and mirror benchmark JSON reports into `project/reports/results/`.

## Environment

The CLI runner sets these automatically:

- `NODE_ENV=test`
- `BASE_URL`

Other environment requirements depend on the selected suites and providers:

- Provider API keys only for the services used by the selected tests

During execution, the Bun E2E harness runs the local server in `NODE_ENV=test`. That managed runtime suppresses outbound email and clears `RESEND_API_KEY`, so verify/path E2E runs do not send real email.

## Reports

- Unified runner artifacts: `artifacts/logs/test-runs/<runId>/...`
- E2E JSON reports and ad hoc path-run outputs: `artifacts/logs/` by default, or `TEST_RUN_OUTPUT_DIR` when set
- Mirrored benchmark JSON reports: `project/reports/results/<timestamp>-e2e-...-report.json`
- Override the default primary output directory with `TEST_RUN_OUTPUT_DIR`
